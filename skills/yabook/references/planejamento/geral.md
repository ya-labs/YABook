# `$yabook plan`

Inicie uma entrevista geral para identificar o objeto de planejamento. Não faça
diagnóstico do repositório e não crie checklist.

Pergunte em blocos curtos somente o necessário para descobrir se a pessoa quer
planejar uma versão, uma capacidade, uma melhoria de processo ou outro objeto.
Não decida produto, escopo, versão, issue ou documento antes da resposta.

Depois que o objeto estiver claro, direcione para a rota aplicável:

- versão identificada: `$yabook plan start <versão>`;
- tema que ainda precisa de análise: `$yabook discuss <tema>`;
- planejamento já existente: `$yabook plan next`;
- estado atual ainda incerto: `$yabook diagnose`.

`$yabook steps start plan` conduz a mesma entrevista com checklist contextual
ativo. Fora desse atalho, `plan` não inicia nem persiste checklist.
