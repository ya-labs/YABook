# Planejamento YABook

Leia somente a subreferência da rota:

| Comando | Referência |
| --- | --- |
| `plan` | `geral.md` |
| `diagnose [full]` | `diagnose.md` |
| `plan start <versão>` | `start.md` |
| `plan status`, `plan next` | `status-next.md` |
| `plan review` | `review.md` |
| `plan brief` | `../briefs.md` |
| `plan roadmap`, `do plan roadmap` | `roadmap.md` |
| `do plan` | `persistencia.md` |

Princípios comuns:

- diagnóstico observa; planejamento decide;
- documentação guarda conhecimento estável;
- GitHub guarda andamento operacional;
- planeje a versão em alto nível e detalhe apenas o próximo bloco;
- decisões recentes e entregas reais prevalecem sobre texto antigo;
- sem `do`, não altere arquivos nem sistemas externos.
- use `plan brief` válido antes de reler a discussão ou documentos longos.
