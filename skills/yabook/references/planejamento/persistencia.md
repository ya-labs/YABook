# `$yabook do plan`

Antes da escrita, apresente o escopo final.

1. Confirme decisões aprovadas.
2. Localize documentos equivalentes e adapte-os.
3. Se faltar rastreabilidade, crie issue e branch de planejamento.
4. Atualize visão, versão, roadmap e decisões.
5. Registre resumo da sessão com contexto, decisões, pendências e impactos.
6. Preserve hipóteses como não decididas.
7. Não crie commit.

Estrutura padrão quando não houver equivalente:

```text
docs/planejamento/
├── visao-do-produto.md
├── roadmap.md
├── versoes/v1.md
└── sessoes/AAAA-MM-DD-assunto.md
```

O resumo não é transcrição nem status operacional. Se a rastreabilidade for
obrigatória e GitHub ou Git estiver indisponível, não edite arquivos.
